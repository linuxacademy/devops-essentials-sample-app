Continuous delivery sample

DevOps is awesome.

A small static site, shipped the way production software should be: built, tested and deployed automatically on every change.

See the pipeline View source

From commit to production

Every merge to master moves through the same four stages.

  1. 01

    Build

    Gradle validates the project and packages the site as a build artifact.

  2. 02

    Test

    Static checks confirm the required files exist and the markup is valid.

  3. 03

    Stage

    The artifact is published to a staging host for a final manual review.

  4. 04

    Release

    After approval the same artifact is promoted to production over SSH.

Architecture

Two pipelines share one repository: GitHub Actions validates every pull request and publishes this site, while Jenkins promotes the packaged artifact to staging and production.

Under the hood

The configuration that drives the pipeline, trimmed to the essentials.

Practices behind it

Pull request workflow

Changes land through reviewed pull requests, and the default branch stays releasable.

Build once, deploy many

One artifact is promoted through each environment, so what was tested is what ships.

Manual approval gate

Production releases wait for an explicit sign-off after staging is verified.

Secrets stay out of code

Credentials live in the CI credential store and are never committed to the repository.
